# AGU 2026: seven-stage agentic software electricity and carbon model

**Status (1 November 2026):** reproducible, source-qualified **illustrative proxy**. The short-task model below can substantially underrepresent production agent use at the day scale: its current 50% scenario yields about 20,400 tokens/day, while a separate [high-load reassessment](HIGH_LOAD_REASSESSMENT_2026-11-01.md) documents published gateway medians of **1.4M tokens/session and 8.6M tokens/active account-day**, plus a P90 of 87M/day. The short-task output is retained as a narrow local-trace case; the high-load results are separate conditional sensitivities. Neither is a measured carbon footprint of replacing an engineer. The current local task attempts have no graded success outcome; the closed-model token traces do not identify the actual serving hardware. Read [the reference register](REFERENCES.md), [source audit](SOURCE_AUDIT.md), and [evidence review](EVIDENCE_EXPANSION_2026-11-01.md) for details.

## Research boundary and data hierarchy

The functional unit is **one engineer's eight-hour paid workday**. [A Microsoft survey of 484 developers](https://arxiv.org/html/2502.15287) reports approximately 11% coding new features, 9% debugging, 6% architecture/design, and 5% PR/code review. These four observed activities sum to about 31% of reported weekly time. An eight-hour day is an explicit normalization, making **2.48 tracked task-hours/day**. The other 69% contains both technical and nontechnical work and is outside the modeled numerator. The survey response rate was 8.06%, and the activity shares are rounded self-reports.

Data priority is: local raw task and GPU measurements; published primary research and agency data; then labeled analyst scenarios. Peak vendor accelerator wattages are specifications, not observed inference power. The [Guidi et al.](https://arxiv.org/html/2606.05420v1) U.S. hyperscale sample supplies the broad source weights; [EIA 2024 generation](https://www.eia.gov/electricity/annual/table.php?t=epa_03_01_b.html) supplies a **proxy** for its unpublished renewable submix, with newly released final 2025 generation as a year sensitivity; [IPCC AR5 Table A.III.2](https://www.ipcc.ch/site/assets/uploads/2018/02/ipcc_wg3_ar5_annex-iii.pdf) supplies source-specific life-cycle factors. The operational comparison still uses [EPA eGRID](https://www.epa.gov/egrid/summary-data) directly. A draw samples a correlated **mix vector** for a scenario, never a single generator for an individual request.

## Seven-stage model

The **poster fan** now uses the high-load branch described below; the short-task branch in the following table remains a separate diagnostic. The common starting unit is **attempted FTE per engineer-day**, where one paid engineer-day is normalized to eight hours. This is an allocation assumption, not measured net job displacement.

### High-load fan branch: FTE/day to CO₂e/day

For a candidate work density `A ∈ {20,40,60}` equal-human-effort units per eight-hour day, each unit represents `8/A` human hours. For a targeted attempted allocation `q ∈ {0.30,0.50,0.70}` FTE/day, sample `N_i ~ Binomial(A,q)`. The **realized attempted FTE/day** in draw `i` is `F_i=N_i/A`; hence `E[F_i]=q`. This equality requires the explicit *equal human effort per candidate unit* assumption. The 3×3 crossed design separates the assumed daily work-unit density from the FTE allocation. Work units are microinteractions, not accepted engineering deliverables.

The stress mapping assumes one delegated unit starts one gateway session. With `T_{s,i} ~ Lognormal(ln(1.4×10⁶),0.7)` tokens/session, `T_i=Σ_{s=1}^{N_i}T_{s,i}`; only the 1.4M median comes from [Standard Compute's Agent Burn Index](https://standardcompute.com/agent-burn-index), while the spread and one-unit-to-one-session mapping are analyst assumptions. With the local H100 single-GPU Qwen3-Coder-30B-A3B proxy (`R=1,642 total tokens/s`, `P=326 W`), `G_i=T_i/R` GPU-s/day; `E_i=G_i P u_i PUE_i / 3,600,000` kWh/day, where `u_i~Tri(1,1.2,1.4)` and `PUE_i~Tri(1.2,1.4,1.6)`. The sampled U.S. source-mix life-cycle intensity is `I_i=Σ_s p_{s,i} EF_{s,IPCC-median}`, with `p_i~Dirichlet(100p₀)`; `C_i=E_i I_i` kg CO₂e/day. The EPA operational comparator is `C^op_i=E_i×0.349667`, reported separately. All outputs are **conditional benchmark-equivalent sensitivities**, not measurements of commercial-agent energy or effective FTE replacement.

The variables below are per engineer-day unless specified otherwise. `k` indexes debugging, feature coding, architecture/design, and PR review; `j` indexes a model or token source; `g` indexes measured hardware; `r` indexes grid region. A subscript `i` denotes Monte Carlo draw `i`.

Fractional `n_k` is an expected rate for work spanning days. |

`Tri(low, mode, high)` is a triangular **scenario distribution**, not a fitted empirical confidence distribution. For the four task types the duration triples are 0.5/2/8 h, 2/8/40 h, 8/20/80 h, and 0.25/2/8 h respectively. [METR's RCT](https://metr.org/blog/2025-07-10-early-2025-ai-experienced-os-dev-study/) found about two hours per selected repository issue across categories, which is a plausibility check only. The short/long bounds and task mapping must be replaced with company time diaries and accepted-task records.

### Step 6: source mix and factor uncertainty

The central annual attributional mix is **38.2% natural gas, 15.2% coal, 20.9% nuclear, 25.3% renewables**, from [Guidi et al.'s 403 U.S. hyperscale facilities](https://arxiv.org/html/2606.05420v1). The published values sum to 99.6% after rounding; the model assigns the **0.4% arithmetic residual** to other fossil with the natural-gas life-cycle factor as a flagged proxy. The paper's aggregate fossil subtotal is 53.9%, which differs by 0.1 percentage point from gas + coal + residual owing to independent rounding. The model does not silently renormalize all four published categories.

Guidi do not publish a complete renewable subcategory vector in the cited text. The 25.3% renewable portion is split in proportion to [EIA 2024 U.S. utility-scale generation](https://www.eia.gov/electricity/annual/table.php?t=epa_03_01_b.html): wind 451,904; solar 219,833; conventional hydro 242,896; biomass 46,422; geothermal 15,407 thousand MWh. These yield whole-mix shares of about **11.71%, 5.70%, 6.29%, 1.20%, and 0.40%** respectively. This is an **analyst proxy** for the unknown 403-site renewable composition; it is not a measured data-center submix. The precise derivation and source-specific low/median/high factors are in [`stage6_grid_source_probabilities.csv`](stage6_grid_source_probabilities.csv). Final [EIA 2025 annual data](https://www.eia.gov/electricity/annual/table.php?t=epa_03_01_b.html), released 21 October 2026, are now included as a **temporal sensitivity** in [`stage6_renewable_split_eia_2024_2025.csv`](stage6_renewable_split_eia_2024_2025.csv); the main 2024 proxy remains closer to the sampled May 2024–April 2025 period.

At the central weights, `Σ_s p_s EF_s` gives **0.275 / 0.325 / 0.573 kg CO₂e/kWh** for IPCC low / median / high life-cycle factor columns. The high envelope is strongly affected by IPCC's **2.2 kg CO₂e/kWh hydropower maximum**, a reservoir-specific extreme; it should not be interpreted as a likely P90 grid intensity. With the median factors fixed and assumed `κ=100`, the model's mix-only P10/P50/P90 is about **0.287 / 0.325 / 0.363 kg CO₂e/kWh**. Each draw treats all sources as one compositional vector with weights summing to one, so an increase in one share is offset elsewhere. For a large number of kWh, `E_facility × Σ_s p_s EF_s` is the appropriate allocation calculation; a categorical source draw for each individual kWh would add artificial sampling noise.

Because `κ` has no fitted empirical basis, [`grid_mix_kappa_sensitivity.csv`](model_outputs/grid_mix_kappa_sensitivity.csv) reports conditional P10/P50/P90 for κ=20, 100, and 500 and for both EIA proxy years. With the **2024 proxy and IPCC median factors**, these are approximately **0.239/0.323/0.408**, **0.287/0.325/0.364**, and **0.307/0.325/0.342 kg CO₂e/kWh** respectively. Smaller κ means wider assumed source-mix variation; none of these is a calibrated 80% confidence interval. At fixed Guidi broad shares, replacing the 2024 renewable split with 2025 changes the IPCC median-factor result from **0.324738 to 0.324917 kg CO₂e/kWh** (+0.000179); the IPCC high-factor envelope falls from **0.572841 to 0.562242** because the newer proxy allocates less of the renewable share to hydro. These are proxy-year differences, not a measured 2025 data-center mix. The central fan uses κ=100 and the 2024 proxy.

The source-mix result is a **life-cycle electricity-supply** scenario. [EPA eGRID2023](https://www.epa.gov/egrid/summary-data) provides the separate U.S. annual average **operational** reference of 0.349667 kg CO₂e/kWh. [Guidi et al.](https://arxiv.org/html/2606.05420v1) report **0.545 kg CO₂/kWh** for their sample using plant-level attribution; our coarse mix combined with global IPCC life-cycle factors does **not** reproduce that result. An audit of the [EPA detailed workbook](https://www.epa.gov/egrid/detailed-data) also finds **0.326 kg CO₂e/kWh** for PJM (BA23 total output), versus Guidi's reported **0.535 kg CO₂/kWh** for PJM. This discrepancy remains unresolved, so the Guidi reported intensity is **not** a calibration target. The [reconciliation note](GRID_SOURCE_RECONCILIATION.md) gives field codes and conversion arithmetic. [EPA guidance](https://www.epa.gov/system/files/documents/2025-01/using-egrid-to-determine-emissions.pdf) recommends the site's eGRID subregion total-output rate for location-based reporting; the national factor is only a fallback while site location is unknown. Neither factor represents marginal emissions from additional demand.

### What a true replacement estimate would require

If `a_k` is the eligible share of category `k`, `p_k` is agent acceptance probability, and `r_k` is the fraction of original human time still used in review/correction, then a future net substitution model is:

`N_accepted,k = (H_k / D_k) × a_k × p_k`;

`FTE_net = [Σ_k N_accepted,k × D_k × (1-r_k)] / H_paid`.

Those `a_k`, `p_k`, and `r_k` have **not** been estimated for this project. The present `q` is attempted work allocation, so the current model does not evaluate `FTE_net`.

## Monte Carlo examples

Each of nine cases runs 10,000 draws. Within a draw, durations, paired token traces, host factor, PUE, and one correlated source-share vector are sampled; work share, model/trace source, hardware cell, the EIA renewable *within-group* proportions, and EPA U.S. operational factor are held fixed. The Dirichlet concentration `κ=100` is an **analyst sensitivity setting**, not an empirical share uncertainty estimate; varying `κ` is a next sensitivity. IPCC source-factor low/median/high are run as **three parallel bounds** on each share draw, not given probabilities. The cases change one major factor at a time around the 50%/GPT-5.4/H100-c1 case. The reported P10–P90 intervals are **conditional scenario ranges**, not confidence intervals for real-world emissions.

`n_k` is a fractional expected task rate and is multiplied by one sampled trace for each family in a draw. Thus the intervals describe uncertainty in a *day-equivalent rate*; they do not model the actual sequence of zero-task and multi-task calendar days. A company-level process needs a compound task-arrival model and separate shared versus engineer-specific variation.

The H100-c64 cell has substantially higher throughput but poor interactive first-token latency; it is not an equivalent service-quality case. The high-context case uses [Standard Compute's](https://standardcompute.com/agent-burn-index) **median session** of 1.4M tokens as an assumed token-per-task anchor, with analyst-selected lognormal spread (`σ=0.7`); their published sessions are not graded tasks. [Bai et al.](https://arxiv.org/html/2604.22750v3) show up to 30× within-task run variation for some cases, but that is not a universal multiplier. [Salim et al.](https://arxiv.org/html/2601.14470v1) show that review and reasoning can be important in a different multi-agent scaffold. The [Iternal guide](https://iternal.ai/token-usage-guide) has no auditable trace sample for its million-token task claim and is excluded from numeric calibration. [Uber](https://www.uber.com/us/en/blog/efficient-software-factory/) and [Meta](https://engineering.fb.com/2026/04/16/developer-tools/capacity-efficiency-at-meta-how-unified-ai-agents-optimize-performance-at-hyperscale/) show enterprise workflow scale but publish no compatible token-per-task statistic.

At 10,000 engineers × 260 days, simply scaling the 50% proxy medians gives about **4.91 MWh/year**, **1.71 t operational CO₂e/year** using EPA or **1.59 t electricity-supply life-cycle CO₂e/year** using the IPCC median-factor mix. This is an arithmetic illustration only: it ignores fleet idle energy, peak capacity, work heterogeneity, correlated site mix, and actual provider hardware. Do not present it as a company footprint.

To make the final AGU estimate publishable, collect: (1) company task-time and role data including review; (2) accepted/failed agent outcomes on the same task distribution; (3) provider-reported fresh/cached input, output, reasoning and retries; (4) prefill/decode throughput, latency, board and host power for the actual agent-shaped trace on each selected model and accelerator; (5) facility location, utilization, PUE and idle allocation. Measure MoE serving as a complete system: active parameters influence arithmetic, while total weights, KV cache, expert communication and quantization determine memory, accelerator count, and energy. The [accelerator](stage4_accelerator_catalog.csv) and [MoE model](stage4_moe_model_catalog.csv) catalogs define candidates, not inferred joules/token.
