# 高负载重新评估：任务、交互轮次与 token 的计数单位

**结论状态：2026-11-01，供 AGU 2026 海报修订。** 原七阶段模型的本地短任务轨迹给出 50% 情景约 **2.04 万 token／工程师日、0.659 g EPA 运营 CO₂e／日**。这只代表四类工时、270 次未评定成功率的本地尝试与 Qwen3-Coder-30B-A3B 硬件代理。它不能代表一个工程师全天使用生产编码 agent 的中位情况。本文件加入独立的高负载敏感性模型，所有能源数仍为**本地开源模型基准等效值**，不称为 Codex、Claude Code 或 Copilot 的实际电力和碳排放。

## 1. 人的工作量：四种分母

| 分母 | 可用观测 | 对本研究的含义 |
|---|---|---|
| 可验收的工程任务 | [Meyer 等的四小时现场观察](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/02/meyer-fse-2014.pdf)：11 位工程师各做过 2–10 个不同任务，平均 4.8 个；“做过”不等于“完成”。 | 简单乘二约 9.6 个不同任务／八小时，是很弱的外推；没有证据证明人人每天完成几十个独立工程交付。 |
| 任务切换、细小操作 | 同一研究平均每小时 13.3 次任务切换、47 次活动切换。 | 每天几十次操作完全可能，但同一任务可以反复被访问。不能把一次切换当成一次新增或完成的工程任务。 |
| Agent 的用户交互轮次 | [微软的 Copilot 生产轨迹](https://arxiv.org/html/2608.00101)覆盖约 1300 万会话；每会话中位数 3 轮用户交互、15 次模型调用。 | 一轮用户交互可触发多次模型调用；与人的“任务”没有稳定 1:1 对应。 |
| Agent 的网关会话与账户日 | [Standard Compute 网关](https://standardcompute.com/agent-burn-index)：会话按同一 key 停顿十分钟切分，日用量按活跃账户统计。 | 会话可能只做一个子步骤，也可能跨越多个工作项；活跃账户未必对应一个全职工程师。 |

以[微软 484 人时间使用调查](https://arxiv.org/html/2502.15287)的四类技术活动占比 31% 作为旧模型分母，遗漏了其它可能被 agent 协助的技术工作。最终 FTE 应按**节省的人类净工时**计算，而不能直接用 agent 处理的微操作数量计算。

## 2. 生产 token 证据与相互制约

| 统计单位 | 公开数据 | 可说的结论 |
|---|---:|---|
| Copilot 单个**用户轮次** | [微软 Table 4](https://arxiv.org/html/2608.00101)：prompt 中位 227,600、P90 1,500,000；cached prompt 中位 217,200；completion 中位 1,900。 | 百万 token 的轮次确实存在，在该总体中约属上十分位；典型一轮低于百万。各列是边际分位数，不应逐行相减或相加当成联合实测。表后正文另报中位 160,200 prompt 和 265 completion，与表格不一致，本项目使用明确列出的 Table 4 并记录此冲突。 |
| Copilot **会话** | 同一论文：工作日每会话平均 prompt 约 1.2–1.7M，周末约 1.9–2.4M；会话中位 15 次模型调用，P90 100.5 次。 | 百万级会话有大型生产数据支持。这些值是**平均**，不能称为会话中位数。 |
| 第三方网关**会话** | [Standard Compute](https://standardcompute.com/agent-burn-index)：1,224 个会话，中位 1.4M token、16 次请求。 | 适合作为百万级 agent 会话的独立锚点；不能自动等同每项工程任务。 |
| 第三方网关**活跃账户日** | 同一来源：303 个活跃账户日，中位 8.6M、P90 87M token；请求数中位 95、P90 491；输入 token 的 87% 是 cache read。 | 支持日尺度数百万至近亿 token 的负载；样本选择、网关使用者构成与“每位工程师”不同。 |
| 同题模型/运行差异 | [Bai 等](https://arxiv.org/html/2604.22750v3)：部分相同 SWE-bench 题目跨运行可达 30 倍 token 差异；某些模型平均比 GPT-5 多约 150 万 token。 | 难题、模型和 agent 设置决定尾部，不能把 30 倍当普遍系数。 |

因此，“每项任务至少百万”仅在把任务定义为一次较完整的**agent 会话**时可作为压力假设；对于一次简单人工操作、每个用户轮次或每个模型请求则不成立。“一轮对话几十 million”没有找到生产总体中位数的支持；若一轮包含许多模型请求、并行子 agent 或极长自动链，它可作为待测的极端情况。[OpenAI 官方模型文档](https://developers.openai.com/api/docs/models/gpt-6-astra)给 GPT-6 Astra 的单次请求上下文窗口为 105 万 token，因此同一 agent 用户轮次要累计几千万 token 必须跨越多次请求。一个模型请求的上下文窗口也不是一日累计 token。缓存重复计入发送 token，但它不等于一次全新 prefill；不能直接按同一 J/token 换算。

## 3. 高负载 Monte Carlo：七阶段关系

本模型单独检验下列两个**不等价**的用量构造，并纳入两条直接观测的网关账户日。所有情景都只计算 *attempted* agent 工作，未实证代理率或成功率。

1. **FTE／工程师日 → 细小操作 → 会话压力情景。** 以八小时为一个标准工程师日，设每日候选细小交互 `A∈{20,40,60}`，**假设每个候选单元占相同人工时间** `8/A` 小时。把 `q∈{0.30,0.50,0.70}` 定义为拟委托的 FTE／工程师日，则 `N_agent∼Binomial(A,q)`，每次抽样实际拟委托 `FTE_i=N_agent/A`，其期望为 `q`。再**刻意**假设每个被委托单元启动一个完整 agent 会话，`T_session∼Lognormal(ln(1.4M),0.7)`，`T_day=ΣT_session`。1.4M 是观测会话中位数；0.7、`A`、等人工工时和操作到会话的映射均为研究者压力假设。这不是每个员工实际完成任务、净节省工时或岗位替代的统计估计。新增 `A×q` 的 3×3 交叉情景，以便把工作密度和拟委托比例的作用分开。
2. **生产用户轮次情景。** 假设一天有 20 次 Copilot 用户轮次；prompt 的对数正态情景曲线由 Table 4 中位 227.6K 和 P90 1.5M 两点约束，`σ=ln(1.5M/227.6K)/1.28155≈1.47`；总 token 用 `T_prompt×(1+1900/227600)` 近似。该比例由边际中位数构造，非配对观测。
3. **外部日尺度检查。** 单独输入网关活跃账户日 8.6M 与 87M token，不再乘每日任务数。
4. **模型与 GPU。** 本地 H100 单卡并发 1 的 Qwen3-Coder-30B-A3B 基准为 `R=1642 总 token/s、P=326 W`；H200 为 `R=2020、P=349 W`。`t_GPU=T_day/R`。这是原测试 8:1 输入:输出、短上下文上的**基准等效时间**，尚未匹配生产轨迹的高缓存比例、长上下文与商用前沿模型。有关 H100/H200、MoE、上下文和批处理差异的[新实验研究](https://arxiv.org/html/2608.28044)明确指出单一 J/token 不足以描述请求能源。
5. **机房电力。** `E_board(kWh)=T_day×P/(R×3,600,000)`；`E_facility=E_board×u×PUE`。`u∼Tri(1,1.2,1.4)` 和 `PUE∼Tri(1.2,1.4,1.6)` 都是情景假设，含义与主模型相同。对 H100 基准，板卡约 **0.0552 kWh／百万 token**；在 `u=1.2、PUE=1.4` 时约 **0.0927 kWh／百万 token**。不是供应商的实测费率。
6. **电网。** [Guidi 等](https://arxiv.org/html/2606.05420v1)提供 403 家美国超大规模数据中心的天然气、煤、核电和可再生能源归属占比；四舍五入差额为 0.4%。可再生能源内部按 [EIA 2024 全美公用事业级发电量](https://www.eia.gov/electricity/annual/table.php?t=epa_03_01_b.html)拆分，明确作为代理。设电源 `s` 的电量权重为 `p_s`，则 `I_LCA,b=Σ_s p_s EF_IPCC,s,b`（`b` 为 IPCC 低／中／高因子列）。中心占比的 `I_LCA` 为 **0.275／0.325／0.573 kg CO₂e/kWh**；最大值受水电特定水库极端因子影响。抽样时用**研究者假设**的 `Dirichlet(κ=100)` 产生一组相关电源占比，而非给每个请求随机抽一座电厂。美国 2023 年 [EPA eGRID](https://www.epa.gov/egrid/summary-data) 年平均运营系数 `I_op=0.349667 kg CO₂e/kWh` 单独计算。IPCC 因子范围不是概率分位数。
7. **两条排放结果。** `C_LCA,b=E_facility×I_LCA,b`；`C_op=E_facility×I_op`。前者只涵盖**电力供应全生命周期**，后者是**发电运营排放**，两者不相加。[Guidi 论文](https://arxiv.org/html/2606.05420v1)另报告样本运营强度 0.545 kg **CO₂**/kWh；这里的粗分类加权结果无法复现它，需要发电厂级数据核对，因此不把它当作本模型验证。服务器闲置分摊、硬件制造、训练、数据中心扩建与真实前沿模型拓扑仍未核实。

对于更大的多 GPU 模型，不能把“总 token 数 × 30B 单卡 J/token”当成物理定律。更合适的目标是按**实际模型请求**记录 `E_request = E_prefill(新输入, 缓存读写, 上下文, 模型, GPU 拓扑, 批量) + E_decode(输出和推理 token, 同一配置) + E_idle_alloc`。多 GPU 总板卡功率应为 `Σ_g P_g`，吞吐量须按同一服务质量、同一请求形状实测；MoE 的激活参数较少不消除全部模型权重、KV 缓存和专家通信的内存与能耗。[H100/H200 请求能源研究](https://arxiv.org/html/2608.28044)的实验也显示上下文、批量与输出长度会改变每 token 能耗。若仅用未知映射系数 `λ=E_真实/E_30B基准` 做代数压力检查，40×50% 情景的 EPA 运营排放约 1.14 kg CO₂e 可写成 `1.14×λ kg`；`λ=0.1、1、10` 分别约为 0.114、1.14、11.4 kg，**这些 λ 值没有被本项目校准，不是估计区间**。

这些是**条件情景区间**，不是对真实全职工程师或供应商设施排放的置信区间。每情景模拟 10,000 次，现有 13 个情景共 130,000 次抽样，固定随机种子 20261102。详见 [`run_high_load_sensitivity.py`](run_high_load_sensitivity.py) 和 [`high_load_summary.csv`](model_outputs/high_load_summary.csv)。逐次数据 `high_load_draws.csv` 可由脚本重算，不纳入公开仓库。

## 4. 接下来如何把情景变成可发表估计

对同一家企业连续采样工程师日记、issue/PR 关闭记录、agent 用户轮次与模型调用 ID，建立 `工程任务 ↔ 人工细小操作 ↔ agent 会话 ↔ 模型调用` 的配对表。按任务类别记录人工基准工时、agent 成功率、人工审查与返工工时，才能估计净 FTE。对每次模型调用另记新输入、缓存读写、输出与隐藏推理 token、模型、硬件、请求长度、批量、板卡/主机电力和数据中心地点。能源应优先在同一请求形状上测量 prefill、decode 与缓存复用；全机房电力须包含可归属闲置分摊。这样的记录可以用七阶段公式重新抽样，给出可信的企业级区间。
